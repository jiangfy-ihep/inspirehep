### Rootless Docker: one-time administrator preparation

The attempted configuration uses rootless Docker: both the daemon and
containers would run under the development account's user namespace. Docker group membership only
allows access to a root-owned daemon; it is not needed for this rootless socket.
Follow [Docker's rootless prerequisites](https://docs.docker.com/engine/security/rootless/).

Systemd is already installed, but it is not PID 1. Installing it again does not

administrator-approved change to the Pod startup and cgroup delegation, rather
than a package installation. This workflow uses neither `systemctl --user` nor
`loginctl`; start `dockerd-rootless.sh` directly.


### Nested Docker prerequisites and failures

The current `/sys/fs/cgroup` mount is cgroup v2 and read-only. PID 1 has
`CAP_SYS_ADMIN` and `CAP_NET_ADMIN` in its capability set, but that alone does
not prove all inner-container operations work. A daemon can start while
workloads fail when creating cgroups, mounts, or bridge networking.

Without systemd and delegated cgroups, rootless Docker does not provide the
usual cgroup-based `--cpus`, `--memory`, or `--pids-limit` enforcement; do not
assume Compose limits are effective. The outer Pod's limits still bound the
workspace. Slirp4netns/RootlessKit provide user-space networking; verify each
published port from native applications and from outside the Pod. Rootless mode
does not create Kubernetes Services or bypass NetworkPolicy. See
[Docker's rootless resource limits](https://docs.docker.com/engine/security/rootless/tips/#limiting-resources).

If startup or the smoke test fails, report the first error to the cluster
administrator. They must check the approved nested-container capability and
security profile, cgroup access/delegation, storage driver/filesystem, and
networking. Do not remount node cgroups, enable blanket privileged mode, or
disable Docker firewall management as generic fixes. Workspace user-group
permissions cannot fix those cluster-level constraints.

Do not assume Docker stores data in `/data/docker`, point its data root at the
shared project directory, or change storage drivers against existing Docker
data. The administrator should provide suitable storage and a persistence plan;
the workspace writable layer may be replaced with the Pod. If nested Docker is
unsupported, use an administrator-provided engine or Kubernetes infrastructure.
A remote engine needs a matching topology: `localhost` ports and Compose bind
mounts refer to the engine's machine, not automatically to this workspace. The
commands below assume a working nested engine in this workspace.

#### PostgreSQL and the NFS soft-mount limitation

Do not place PostgreSQL's live data directory on either current `/aifs` mount.
PostgreSQL requires an NFS data filesystem to use `hard`; `soft` can return I/O
errors during network failures. NFS itself is not categorically unsupported,
but an administrator must validate the mount, server export durability/fsync
behavior, and permissions before using it for database data. See
[PostgreSQL's NFS requirements](https://www.postgresql.org/docs/14/creating-cluster.html#CREATING-CLUSTER-NFS).

Ask the storage/cluster administrator about any mount or export changes; do not
remount the shared `/aifs` filesystems from this workspace. A `hard` mount would
address that PostgreSQL requirement, but would not make NFS suitable for
rootless Docker or Podman engine storage.

NFS remains a place for database dumps, import JSON, and backups, for example
under the proposed `/aifs/user/data/jiangfayu/inspirehep-data/backups/`. Check
backup command results and test restores. Use database-aware backup tools;
copying a running PostgreSQL data directory is not a substitute for a valid
backup procedure. This example directory was not created during documentation.

Configuration files may stay in the NFS home while `graphroot` is relocated.
See [Podman rootless storage limitations](https://docs.podman.io/en/latest/markdown/podman.1.html#note-unsupported-file-systems-in-rootless-mode).

permissions `0700`. Without a login service manager, `XDG_RUNTIME_DIR` may not be

Have the required Podman, networking, and FUSE packages installed before a trial.
Where needed, `fuse-overlayfs`
supports rootless image layering; the workspace's overlay-backed filesystem
still needs an actual storage/container smoke test. Do not change a populated
engine's graphroot/driver or assume all services work by aliasing `docker`.

Application bind mounts and engine storage are different concerns. A non-NFS
graphroot does not make mounted PostgreSQL data durable or correct an NFS
`soft` mount. Rootless UID/GID mapping also needs to match data-directory
permissions. The existing read-only cgroup and Compose resource-limit concerns

## 8. Imports, tests, shutdown, and synchronization

Run imports in an environment-loaded backend shell. The CLI writes directly to
the database and index; importing local files does not require a running HTTP
server or an API token:

```bash

```

URL imports fetch raw JSON from the **source** API. `--token` authenticates to
that source, not the local backend. A token generated by your local instance

```bash
poetry run inspirehep importer records \
  -u https://inspirehep.net/api/literature/20 --token "$SOURCE_API_TOKEN"
```

`import_records.sh` and `IMPORT.md` symlinks require a separate

| Directory | Check |
| --- | --- |

| `ui/` | `yarn test:unit`; `yarn test` for lint, types, coverage, bundle size |

check against an existing instance. Cypress defaults to port 8080; a native UI

For daily shutdown, stop the native processes with `Ctrl+C`, then use `dc stop`

anonymous database volumes may not be reattached on the next `up`. Back up data
before removing containers or volumes. MinIO alone has an explicitly named
volume in the local override; do not assume all services share that persistence
configuration. Even `dc stop` does not protect overlay-backed data against
workspace replacement; follow the storage plan above for durable services.

```bash
git merge upstream/master
# Resolve conflicts and run the affected checks before publishing.

```
